Short-lived certificate configuration — set in environment / config file
CA Key Path {{ config.SSH_CA_KEY_PATH }}
Path to the private key used to sign SSH certificates.
Certificate TTL {{ config.SSH_CERT_TTL_SECONDS }}s
{% set ttl = config.SSH_CERT_TTL_SECONDS %} Each certificate is valid for {{ ttl // 3600 }}h {{ (ttl % 3600) // 60 }}m. Shorter TTLs reduce the window of misuse if a cert is intercepted.
Replay Window {{ config.CERT_REQUEST_REPLAY_WINDOW_SECONDS }}s
Certificate requests with identical challenge nonces are rejected within this window to prevent replay attacks.
Public Key URL GET {{ request.host_url }}api/v1/cert/ca.pub
Used in TrustedUserCAKeys on enrolled servers.
Certificate Flow
  1. Device agent signs a cert request with its passkey (device private key)
  2. Platform verifies device trust status and evaluates access policies
  3. If approved, platform signs a short-lived SSH certificate with the CA key
  4. Certificate includes the Unix principal(s) from the matching access grant
  5. SSH server validates the certificate against TrustedUserCAKeys
  6. Session is recorded in the audit log
Server-side setup
Add to /etc/ssh/sshd_config:
TrustedUserCAKeys /etc/ssh/trusted_ca.pub
Fetch the CA public key:
curl {{ request.host_url }}api/v1/cert/ca.pub > /etc/ssh/trusted_ca.pub
